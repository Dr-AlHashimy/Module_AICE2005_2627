# AICE2005 — Systematic Design

## Educational Aims

- **a1**: Understand the importance of defining clear APIs and component boundaries
- **a2**: Understanding of tools (both processes and software) for managing group-work
- **a3**: Knowledge of best practices for managing small group projects and identifying risks
- **b1**: Decompose a system into a set of loosely coupled components
- **b2**: Define APIs and interfaces between components
- **b3**: Identify appropriate languages for implementing parts of a system
- **b4**: Understand the tradeoffs between off-the-shelf and bespoke components
- **b5**: Identify ethical and security responsibilities with respect to data in motion and at rest
- **d1**: Use test frameworks to perform integration tests for existing components
